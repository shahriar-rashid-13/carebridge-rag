# carebridge-rag

Synthetic RAG corpus for the CareBridge clinic app (Assessment 2, "RAG on 5,000+ records"), plus
the script that embeds it and uploads it to Supabase. All people, doctors, and records are
fictional.

Whole-system overview: `../PROJECT_OVERVIEW.md`. Search and the AI tool live in
`carebridge-clinic-flow` (table `rag_documents`, RPC `match_rag_documents`, tool
`search_knowledge`).

## How it fits together

```text
catalog + seed --> manifest (facts) --> LLM writes text --> validator --> corpus_clean.jsonl
corpus_clean.jsonl --> embed-upload.mjs --> LiteLLM carebridge-embed (768 dims)
                                        --> Supabase rag_documents (upsert by doc_id)
App question --> Edge Function search_knowledge --> match_rag_documents (hybrid search) --> answer
```

## Contents

| Path | What it is |
|---|---|
| `SPEC.md` | Corpus specification: clinic facts, doctors, diagnoses, record rules, batch plan, validator checks |
| `GENERATION_PROMPT.md` | Prompt and message templates used to have an LLM write the record text |
| `RAG_PLAN.md` | Agreed RAG design, build order, and progress |
| `scripts/catalog.mjs` | Controlled vocabulary (specializations, doctors, diagnoses, medicines, FAQ facts) |
| `scripts/generate-manifest.mjs` | Deterministic fact manifest (seed 20260929) |
| `scripts/validate-batch.mjs` | Checks LLM output against the manifest and writes fix messages |
| `scripts/render-prescriptions.mjs` | Writes prescription text directly from the manifest for slices not generated by an LLM |
| `scripts/build-corpus.mjs` | Re-validates all output and merges it with the manifest into the clean corpus |
| `scripts/embed-upload.mjs` | Embeds the corpus through LiteLLM and upserts it into Supabase `rag_documents` |
| `corpus/corpus_clean.jsonl` | Final clean corpus: one record per line with text and metadata |
| `corpus/summary.json` | Counts by type, specialization, and generator; excluded records |
| `manifest/` | Generated facts: doctors, patients, visits, FAQ intents, and 50-row LLM input slices |
| `output/` | LLM-written CSV per slice (`<slice>.csv`, optional `<slice>.fixN.csv`) plus validator reports |

## Commands (Node 20+, no dependencies)

Corpus:

```bash
node scripts/generate-manifest.mjs        # rebuild manifest/ (deterministic)
node scripts/validate-batch.mjs           # validate every non-empty slice in output/
node scripts/validate-batch.mjs B01-M01   # validate one slice
node scripts/render-prescriptions.mjs     # fill empty prescription slices from the manifest
node scripts/build-corpus.mjs             # write corpus/corpus_clean.jsonl and corpus/summary.json
```

Upload: create `.env` in this folder (gitignored, never commit it):

```text
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<Supabase secret key, sb_secret_...>
LITELLM_BASE_URL=https://carebridge-lite-llm.vercel.app
LITELLM_MASTER_KEY=<gateway master key>
```

The service role key is the Supabase **secret** key, not the publishable key. Only the service
role can write to `rag_documents`.

```bash
node scripts/embed-upload.mjs --batch 50 --pace 31000   # full run, stays under the per-minute limit
node scripts/embed-upload.mjs --limit 100               # test with the first 100 pending records
node scripts/embed-upload.mjs --force                   # re-embed rows that already have embeddings
```

- Rows that already have an embedding are skipped, so a stopped run can be restarted with the same
  command.
- `--batch` sets texts per embedding call (default 50); `--pace` sets milliseconds between batches.
- HTTP 429 and 5xx responses are retried with backoff. When the daily quota is used up, retries
  fail and the script stops with an error; run it again after the quota resets.
